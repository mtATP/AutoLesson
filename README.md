# AutoLesson

让蓝色大肥鱼 Vibe Coding 了一个基于纯视觉的智慧树刷课脚本。

基于**纯视觉**的智慧树（`studyvideoh5.zhihuishu.com`）网课自动观看脚本。

不注入 JavaScript、不读取 DOM、不修改页面请求，只做三件事：

1. 截屏；
2. OCR / 颜色与形状识别；
3. 像人一样移动鼠标、点击。

脚本会按顺序观看当前科目的所有视频，自动续播、处理弹题与公告、检测暂停/卡顿，并在无法安全继续时**立即停止并通知**。`run` 模式**不会**点击「平时测试」，也**不会**拖动进度条；新增的 `practice` 命令专门处理平时测试，但**只暂存、绝不提交**。

## 一、需求对照

| 要求 | 实现 |
| --- | --- |
| Python 脚本挂机完成一个科目的所有视频 | `autolesson/controller.py` 状态机 + 右侧目录逐条处理 |
| 纯视觉检测播放状态、进度、继续 | `vision.py` 进度条轨道/蓝色播放头 + 时间 OCR + 播放/暂停图标形状 |
| 网络中断等外部原因停播时实时发现并继续 | 进度/时间双通道监测，暂停自动点播放，卡顿多次恢复，超时通知停止 |
| 大模型辅助答题 | `llm.py` + `quiz.py`，默认 DeepSeek V4.1 Flash 原生多模态，JSON 输出 |
| 自动练习（平时测试） | `practice` 命令：新标签页、截图 LLM 作答、跳过已答/已提交、**只暂存不提交** |
| 节约 Token，只在答题时用大模型 | OCR 优先；仅弹题调用；文字题不发图；数学题才发裁剪图；关闭 thinking；答案缓存 |
| 善用 OCR | RapidOCR（PP-OCRv6）离线识别目录、时间、弹窗、题干与选项 |
| 完善异常监测，故障即停并通知 | 登录失效/人脸验证/无法关闭弹窗/长时间卡顿等均 `FatalError`，保存截图 + 桌面/声音/Webhook |

## 二、工作流程

```text
启动
 ├─ 检查屏幕 / 自动标定右侧目录面板
 ├─ 全量滚动扫描目录，建立视频清单（run 跳过“平时测试”）
 ├─ 选择第一个未完成视频
 │    ├─ 点击标题 → 用左上角面包屑确认切换成功
 │    ├─ 等待播放器加载 → 唤出控件 → 点击播放
 │    ├─ 每 4 秒循环：
 │    │    ├─ 检测浅色弹窗：弹题 / 学前必读 / 每日进度 / 公告 / 登录 / 验证
 │    │    ├─ 读取进度条、时间、播放/暂停图标
 │    │    ├─ 暂停 → 点播放；卡顿 → 暂停/继续 + 重试
 │    │    ├─ 网络异常 → 等待恢复；多次失败 → 停止并通知
 │    │    └─ 到达结尾 → 校验平台“已完成”蓝色勾
 │    └─ 平台未标记完成 → 重试一次 → 仍失败则停止并通知
 └─ 全量复核；全部完成 → 通知并退出
```

关键技术点：

- **目录状态**：右侧每行有视频时长（`00:19:36`），“平时测试”没有时长，因此只处理“有时长”的行；右侧蓝色实心圆 = 已完成，蓝色空心环 + 百分比 = 学习中。
- **进度**：在播放器底部寻找 80% 以上像素为浅色、同时含蓝色像素的长条；蓝色最右端即播放头。时间文字只作为精确校验，两者互相兜底。
- **播放状态**：暂停/播放按钮位于时间文字左侧。用局部对比度提取图标轮廓：两条竖线 = 正在播放，一个三角形 = 已暂停。
- **弹窗**：找到播放器区域内的大块浅色卡片，再 OCR 卡片顶部文字分类。白色 PPT 页也会被当成卡片，脚本会用尺寸、位置和关键词二次确认，不会乱点。
- **弹题**：OCR 题干与选项；题目显示不全时在弹窗内部滚动合并；普通题发文字，数学/公式/OCR 不完整时附带题目截图；点选后等待平台显示“正确答案”，再点“关闭”。若大模型连续返回空内容，会自动在“文本↔图片”之间切换后再试一次。

## 三、安装

### 方式 A：一键部署（推荐，零基础）

双击项目根目录的 **`一键部署.bat`**。脚本会自动：

1. 查找 Python 3.10～3.12；没有则优先从**清华/华为镜像**下载安装 **Python 3.12**（当前用户，无需管理员）；
2. 创建项目专用虚拟环境 `.venv`；
3. 用 **清华 PyPI 源**安装 `requirements.txt` 全部依赖，失败时自动改用官方 PyPI 重试；
4. 验证 OpenCV、OCR、截图、鼠标、GUI 等模块是否可用。

首次约 5～15 分钟。看到 `[完成]` 即可双击 `启动GUI.bat`。
脚本只写入本项目目录和当前用户的 Python，不修改系统设置。
如果公司/学校电脑禁止安装软件，请让管理员放行 Python，或使用下面的手动方式。

### 方式 B：手动安装（开发者）

推荐 **Python 3.10～3.12**（优先 3.12），Windows 10/11 优先适配。Python 3.13/3.14 在部分网络环境下缺少 onnxruntime/numpy 的 Windows wheel，不要用。

```bash
# 1. 进入项目目录
cd AutoLesson

# 2. 创建虚拟环境（可选但推荐）
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

# 3. 安装依赖
pip install -r requirements.txt
```

依赖说明：

- `rapidocr` + `onnxruntime`：离线中文 OCR，首次运行会加载模型；若模型缺失会自动下载。
- `mss`：毫秒级截屏。
- `pyautogui`：鼠标控制。**Windows** 安装即用（请用与浏览器相同的用户权限运行，不要以管理员身份运行）；**macOS** 需在“系统设置 → 隐私与安全性”中授予终端/IDE **屏幕录制**与**辅助功能**权限；**Linux** 还需要 `python3-xlib`、`scrot` 和 X11 会话（Wayland 下截屏可能不可用）。
- `pygetwindow` / `plyer`：可选，用于窗口聚焦与桌面通知。缺失时自动降级，不影响主流程。

## 四、配置大模型

默认使用 **DeepSeek V4.1 Flash**：API 模型名 `deepseek-flash`（版本 `DeepSeek-V4.1-Flash-1017`）。
它原生支持**文字 + 图片**，所以不需要再单独配置视觉模型，数学/矩阵题会把裁剪图直接发给同一个模型。

官方文档：

- [Vision](https://api-docs.deepseek.com/guides/vision)
- [Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing)
- [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode)
- [JSON Output](https://api-docs.deepseek.com/guides/json_mode)

### 方式 A：环境变量（推荐）

Windows CMD：

```bat
set DEEPSEEK_API_KEY=sk-xxxxxxxx
```

PowerShell：

```powershell
$env:DEEPSEEK_API_KEY="sk-xxxxxxxx"
```

macOS / Linux：

```bash
export DEEPSEEK_API_KEY="sk-xxxxxxxx"
```

### 方式 B：直接写进 `config.yaml`

```yaml
llm:
  base_url: https://api.deepseek.com
  api_key: sk-xxxxxxxx
  model: deepseek-flash
  vision_model: ""       # 留空 = 与 model 相同（原生多模态）
  json_mode: true        # DeepSeek 原生 JSON 输出
  thinking: false        # 弹题求快，关闭思考模式
```

> 旧模型名 `deepseek-v4-flash` / `deepseek-v4-flash-vision-exp` 仍被接受，但官方建议统一使用 `deepseek-flash`。

### 关于 thinking 和 JSON 模式

- 默认 `thinking: false`：弹题只是选择题，关闭思考可以降低延迟和输出 token。需要更充分的推理时改成 `true`（此时 `temperature` 不生效）。
- 默认 `json_mode: true`：使用 DeepSeek JSON Output 返回严格 JSON。如果换成不支持 `response_format` / `thinking` 的接口，脚本会自动去掉这两个字段重试，不会直接失败。
- `max_tokens` 默认 400，足够输出 `{"answers":...,"confidence":...,"reason":...}`；若开启 `thinking`，建议调到 800~1200，避免 JSON 被推理过程截断。
- JSON 模式偶尔返回空内容时，脚本会自动去掉 `response_format` 再试一次。

### 切换其他模型 / 其他兼容接口

只要支持 `POST {base_url}/chat/completions` 与 `Authorization: Bearer <key>` 即可，例如 Qwen、OpenAI、硅基流动、Moonshot 等：

```yaml
llm:
  base_url: https://dashscope.aliyuncs.com/compatible-mode/v1
  api_key_env: DASHSCOPE_API_KEY
  model: qwen-vl-max
  vision_model: ""
```

- 多模态模型把 `vision_model` 留空即可复用 `model`；
- 纯文字模型保持 `vision_model` 为空，并保留 `quiz.image_fallback_text: true`：图片请求被 400/422 拒绝时会自动改为纯文本作答；
- 注意：`deepseek-v4-pro` 目前不支持图片；如果用它，请把 `vision_model` 指向一个多模态模型，或依赖纯文本降级；
- 图片仍按 OpenAI 兼容的 `image_url` + base64 data URL 发送，DeepSeek 支持 JPEG/PNG/GIF/WebP。

> API Key 只用于请求头，不会写入日志或状态文件。

## 三种运行模式

| 模式 | 命令 | 说明 |
| --- | --- | --- |
| 顺序视频 | `python -m autolesson run` | 只按目录顺序看未完成视频，跳过平时测试 |
| 顺序题目 | `python -m autolesson practice` | 只按目录顺序处理未完成平时测试，只暂存不提交 |
| 列表混合 | `python -m autolesson auto` | 按当前目录可见行的上下顺序，视频/平时测试谁在前先做谁 |
| 图形控制台 | `python -m autolesson gui` | 选择模式、修改全部配置、启动/停止并实时看日志 |

Windows 下可直接双击项目根目录的 `启动GUI.bat`，或运行 `python -m autolesson gui`。图形控制台使用标准库 tkinter，无需额外安装：顶部选择 `run/auto/practice`，设置页按 `window/layout/panel/ocr/player/practice/quiz/llm/overlay/notify/runtime/safety` 分组，启动前可勾选“清空记录”，运行中可实时查看日志并一键停止；“置顶小条”默认勾选并在启动时显示在屏幕上方，带开始/停止、× 关闭按钮和实时日志行；任务结束 10 秒后或空闲 2 分钟后自动收起，也可以重新勾选打开。

`auto` 模式会实时扫描右侧目录，把“未完成视频”和“未完成的平时测试”按行 y 坐标合并排序；已打蓝勾的视频/测试直接跳过。处理平时测试时复用 `practice` 的截图作答、已答跳过、只暂存不提交逻辑。

平台在“确定暂存”后会自动关闭考试标签；关闭标签前会检查前台窗口标题/页面特征，只有明确是考试页才按 Ctrl+W，自动回到课程页后不会再误关“课程学习”标签。

## 五、快速开始

### 1. 离线自检（不操作鼠标）

```bash
python -m autolesson selftest
```

使用项目内置的课程截图验证目录、状态、进度条、弹题、公告等识别逻辑，并在 `runtime/selftest/` 输出标注图。应为 `21/21 通过`。

### 2. 标定当前位置

打开智慧树课程学习页，登录，保持窗口可见（不要最小化），然后：

```bash
python -m autolesson calibrate
```

它会截图并打印右侧面板位置、识别到的视频与状态，输出标注图 `runtime/shots/calibration.png`。

- 默认 `layout.auto_calibrate: true`，通过 OCR 寻找“目录”二字自动定位，通常**无需手动填坐标**。
- 如果标注图显示面板位置不准，把打印出的 `panel_left` / `panel_top` 填进 `config.yaml`。

### 3. 先跑一个视频试试

```bash
python -m autolesson run --max-lessons 1
```

观察日志与鼠标动作是否正常。确认无误后：

```bash
python -m autolesson run
```

脚本会自动处理当前科目的全部未完成视频，完成后通知退出。

> **运行前检查**
> - 课程学习页所在**标签页处于激活状态**（脚本只认当前画面）；
> - 页面保持在右上角的**白昼（浅色）模式**；
> - **不要进入播放器全屏**（全屏后右侧目录消失，脚本无法选择下一节）；
> - 不要最小化窗口、不要锁屏或让显示器休眠；
> - **运行期间不要移动鼠标或操作该窗口**。

### 4. 自动练习（平时测试，只暂存）

先保持课程学习页在前台，然后：

```bash
python -m autolesson practice
```

脚本会扫描右侧目录里的「平时测试」，**点击前先看行右侧是否已有蓝勾**，已完成直接跳过；逐个点开新标签页，截图题目调用多模态模型作答；**已经作答的题目不重复作答**。已经提交/无法再次提交、以及“得 分/本题的得分/评语”这种成绩结果页也会直接跳过。新标签短暂白屏时不会当作完成，会等待最多 30 秒并重试。全部题目完成后只点击 **「暂存作业」**，并在“确定要暂存作业吗”弹窗里点“确定”。

> **安全红线**
> - **绝不点击「提交作业」**，代码里没有提交点击路径；
> - 如果出现“确认提交本次作业吗”，脚本只会点“取消”，不会点确认；
> - 只处理出现「暂存作业」的页面；没有暂存按钮的页面直接跳过；
> - 已完成（蓝勾）的平时测试在点击前就跳过，不会进入成绩页；
> - 白屏/加载慢只重试，不标记完成；
> - 暂存确认弹窗只点“确定”；平台确认后若自动关闭标签，脚本检测到已回到课程页（“目录”）后不会再按 Ctrl+W 关掉课程页；
> - 题数优先读页面“题目数/总题数”，读不到用答题卡最大数字，绝不轻易用兜底 10；最后一题只点右上角“暂存作业”，不点题目底部那个“保存”；
> - 含图片的题目只点选项左侧圆点/复选框，不点题目图片中心；误开图片查看器（底部出现 1:1 工具栏）时自动按 Esc，仍不关则点右上角 X 退出；
> - 练习与学生平时成绩挂钩，请先在一门不重要的课验证。

如果练习标签页已经手动打开，可以只处理当前页：

```bash
python -m autolesson practice --page --keep-open
```

`--keep-open` 保留标签页方便检查；不加则处理完自动关闭。`--max-tests N` 限制本次处理的平时测试数量。

### 5. 只分析不点击

```bash
python -m autolesson run --dry-run
```

鼠标动作只写日志，适合在陌生分辨率下验证识别是否准确。

### 6. 分析一张现场截图

```bash
python -m autolesson inspect --image runtime/shots/debug.png --annotate runtime/shots/annotated.png
```

会输出布局、视频清单、播放器状态、弹窗分类和弹题解析结果，便于排查。

## 六、配置说明（`config.yaml`）

| 配置 | 默认 | 说明 |
| --- | --- | --- |

### 性能与 CPU

目录扫描和播放监控做了专门优化：

- **滚动不再逐格 OCR**：每页滚动约 450px（由 `panel.scroll_step` 控制），拆成多个 60px 小滚轮事件连续发送，避免 Chrome 截断单次大 delta 导致“40 页只滚了几行”。滚轮只比较目录文字区域指纹，排除右下角 AI 助教动画；到底后指纹连续不变才结束，最多 40 页。若 40 页仍未到底，脚本会停止并报“目录扫描不完整”，不会拿残缺目录去选视频。
- **OCR 限线程**：默认 `ocr.intra_threads: 1`、`inter_threads: 1`、`cv_threads: 1`，单核跑 OCR，不会再把所有 CPU 核心打满。
- **降低检测上采样**：`ocr.det_limit_side: 416`（原默认 736）。小图不再被大幅放大，OCR 单次耗时约减半，识别结果保持一致。
- **关闭方向分类器**：`ocr.use_cls: false`，网课界面文字都是水平的，省掉每个文本框的方向判断。
- **高进度进度条**：进度条按“浅色轨道 + 蓝色已播部分”识别，播放到 70%/90% 时不会因为蓝色占多数而判定为没有进度条。
- **滚动指纹排除右侧动画**：只比较目录文字区域，右侧状态图标/滚动条/加载动画不会让脚本误以为目录还在滚动，避免一直扫到 40 页。
- **失败重试同一个视频**：播放器加载或点击失败时，先回到同一个视频重试一次，不再跳到列表里的其他视频；连续失败 2 次才停止通知。
- **完成状态缓存**：本轮曾看到蓝色勾的视频，后续滚动瞬间偶尔读成“未学习”时不会重复点击；如果当前显示“学习中”，仍会继续观看。
- **白底 PPT 不重复 OCR**：铺满播放器宽度的浅色区域会先按尺寸排除，只有真正的窄弹窗才做文字识别。
- **只截目录区域**：滚动时用 `mss` 只截右侧面板算指纹，避免每 60ms 复制整屏。

调参建议：

- CPU 仍然偏高：保持 `ocr.intra_threads: 1`，并检查是否有其他程序占用；
- OCR 太慢、CPU 有余量：`ocr.intra_threads: 2~4`，或把 `ocr.det_limit_side` 调回 `480~736`（更慢但更保守）；
- 扫描太慢：把 `panel.scroll_step` 从 `-5` 调到 `-8 ~ -10`（每页跳得更远）；
- `panel.scroll_wait` 是**最长**等待时间，检测到稳定会提前结束，通常不需要调大。

## 七、异常与安全机制

### 自动暂停/恢复

- 检测到“暂停图标”且 12 秒无进度 → 点击播放。
- 播放中 45 秒无进度 → 暂停/继续刷新缓冲，最多 3 次。
- 仍无进展 → OCR 检查网络提示；等待最多 120 秒；仍失败 → **停止 + 通知**。
- 找不到进度条 60 秒 → 检查左上角面包屑是否已切走，否则停止。

### 立即停止并通知的故障

- 登录失效、扫码登录页；
- 人脸识别、验证码、滑块、摄像头等平台验证；
- 无法识别课程页面 / 目录为空 / 面板被遮挡；
- 视频播放完但平台始终不标记完成（重试后）；
- 弹题识别失败、大模型无有效答案、选项点击失败、弹窗关不掉；
- 屏幕全黑（锁屏/息屏/远程断开）；
- 连续多次恢复仍无进展。

停止时会：

1. 保存现场截图到 `runtime/shots/`；
2. 写入完整日志 `runtime/logs/`；
3. 控制台 + 桌面 + 声音 + Webhook 通知；
4. 退出码 `2`（配置错误为 `1`，用户中止为 `130`）。

### AI 助教处理

启动时会先检查右侧 AI 助教弹窗/悬浮球：弹窗用固定界面文案识别，悬浮球直接用原图做多尺度模板匹配；找到悬浮球后不再点 X 收起，而是**直接拖动悬浮球本身**到目录面板上方，避免“收成标签再拖标签”的两步操作。没有悬浮球的页面会明确跳过，不会误点。

该功能默认开启，可在 GUI 的“弹窗识别”页或配置中关闭：

```yaml
overlay:
  ai_assistant_cleanup: false
```

### 防误触设计

- **run 不点击平时测试**：只处理带视频时长的行；标题为“平时测试/平时测验/章节测试”直接排除。
- **practice 只暂存**：只点击「暂存作业/暂存」，包含“提交”的按钮一律不点；提交确认弹窗只取消。
- **不拖进度条、不跳转**：只点播放/暂停、视频标题、选项、关闭按钮。
- **点击前确认**：打开视频后用左上角“第X章 X.X、标题”面包屑核对，避免点到别的章节。
- **弹窗二次确认**：白色 PPT 页不会被当成弹窗关闭；不确定的弹窗只记录，不盲点。
- **播放器控制条自动隐藏**：验证播放时只把鼠标移到播放器底部控制条区域唤出进度条，不再点击视频中心（点击会暂停/切换控件），并给慢网络最多 25 秒加载时间。
- **恢复播放顺序**：先点视频**正中央**（`player_center=50%,50%`），等待进度变化；失败才点控制条最左侧播放键。下一节/跳过键在播放键右侧，代码按位置排除，绝不误点。
- **控件唤出位置**：只把鼠标移到视频中央唤出控制条，不再停到左下角；点击播放键前也不会让指针先跑到左下角。
- **蓝色幻灯片兜底**：整屏蓝色会让进度条检测失效；此时改用左下角时间文字（如 00:02:19/00:10:29）构造播放状态，仍能判断暂停/播放与进度。
- **弹题长内容慢速滚动**：正确率优先，弹题每次从顶部开始慢速逐屏扫描（约 180～300px/屏，等待 0.45～0.65s，连续 3 屏不变才停），不再因为“看到一个选项+关闭按钮”就跳过。若滚轮无效，自动拖动弹窗右侧滚动条到底部。
- **长题多图提交**：弹题正文从顶部慢速逐屏扫描，每一屏单独作为一张图提交给多模态模型（默认最多 8 张），不再把 5000px 长图压成一张导致文字糊掉；文本 OCR 仍会合并题干与选项，图文互为兜底。
- **选项完整性按实际最大字母判断**：A/B/C 三选项题就是完整的，不会强行补 D；只有 A/B/D 中间缺 C 这种“空洞”才补 C。少一个选项不再直接致命，扫描后仍少于 2 个才停止。
- **图片选项选择**：只看左侧圆点的蓝色，不把选项图片里的蓝色公式误判为“已选中”；A/B 被矩阵图片挤掉、OCR 只读到 C/D 时，按已知选项行距推算目标行，仍能点到圆点。
- **选项缺失补识别**：首屏不再“看到任意选项+关闭按钮”就认为完整；单选题必须有 A/B/C/D 才跳过滚动。缺 C 等选项时，自动整卡 2.2 倍 OCR、再按 A/B/D 行距裁横带 3 倍 OCR 补回；仍读不到文字才补占位，最终按行距点圆点，避免大模型答 C 却被“C 不在选项”拒绝。
- **弹题全选/未作答提示**：点选项前会清除文本选择；识别到“未作答的弹题不能关闭”提示时，只点**提示卡自己的右上角 X**，不再误点外层弹题的 X/底部关闭；找不到提示卡时**绝不按 ESC**（ESC 会直接关掉答题卡），宁可保持原状重试。关提示后清除选择并重试选项，仍失败则明确停止。
- **正确判分徽标**：平台常把结果和题型粘成“正确 【单选题】”，旧逻辑只认独立一行“正确”，会把已答对的题误判为“未选中”；现在兼容该格式，并先等平台判分再决定是否重试，避免答对后又被清空选择。
- **弹题不重复滚动**：首屏 OCR 已看到选项且关闭按钮在视口内时直接作答，不再滚动；内容不完整时才用鼠标滚轮向下查找，不再拖滚动条（拖拽会选中正文文字）。
- **练习选项滚动**：平时测试页选项被长代码/长题干挤到视口外时，自动向下滚动页面，合并 C/D 等选项；点击答案前再从题目顶部定位目标选项并滚动到可见位置，避免“只看到 A/B 就作答”或点到视口外。
- **练习长题多屏采集**：平时测试也会从题目顶部慢速扫描整页，收集代码/长题的多屏截图和完整 OCR 文本，再交给模型；不再只截当前一屏导致代码缺失。单题识别/作答异常只跳过该题，继续后续题目并最终暂存。
- **练习答题模式顺序**：完整题按“单图→单图重试→纯文本”；不完整题按“拼接图→拼接图重试→不拼接多图→纯文本”。全部失败时**练习模式只跳过该题并回报，不做随机兜底、不点击任何选项**。
- **练习起始题**：进入页面先扫描答题卡题号和蓝色背景，确定当前题/已完成题，从第一个未完成题开始；全部完成时仍会走暂存。
- **两行答题卡定位**：答题卡通常是 1–5 / 6–10 两行，题号高亮会漏 OCR；现在按行分组、行内拟合补号，不再把两行当竖排插值（这是“点第 2 题却唤出 GUI”的根因）。点击前还会校验坐标必须在右侧答题卡区域。
- **速度优化**：弹题首屏选项齐全时直接单图返回；练习页题目完整时不启动 8 屏慢扫，只有长题/选项不全才逐屏采集。
- **练习跳题不点答题卡**：置顶 GUI/小条可能覆盖右侧答题卡，点“第 2 题”会被 GUI 接住。现在统一用底部“下一题/保存”顺序前进，答题卡只用于统计题数，不再作为点击目标。
- **下一题位置与题号校验**：OCR 得到“下一题”文字框后，先点文字中心，再按 0.15/0.35/0/-0.10 倍字高微调；全屏 OCR 漏字时单独放大底部按钮带补识别。每次点击后用正文左侧题号 OCR 校验是否真的翻页；题号没变就重试。仍失败时保留已答内容并继续到**暂存**，不再因为一道题/一次翻页失败退出整个任务。
- **目录一遍扫完**：顶部→底部完整扫描一次，扫描结束只回顶一次；主循环不再额外回顶，避免来回拉列表、漏读长列表。
- **鼠标安全角**：把鼠标甩到屏幕左上角可立即触发 `pyautogui` 安全中止。
- **F9 / ESC**：全局停止热键，浏览器/播放器在前台时也有效；按一次即安全停止并保存状态、生成中止截图。ESC 使用不拦截按键的低级键盘钩子，脚本自己按 ESC 关闭弹题/图片查看器不会误触发停止。
- **Ctrl+C**：控制台在前台时可用；第一次安全停止（保存状态并通知），再按一次强制退出。

## 完成记录与跳过

- 视频完成和“平时测试已暂存/已提交”会写入 `runtime/state.json` 的 `lessons` / `practices`；
- 下次运行会优先跳过这些记录，不再重新打开已暂存的练习逐一确认；
- 想重新处理时，删除 `runtime/state.json`，或运行：

```bat
python -m autolesson run --clear-record
python -m autolesson auto --clear-record
python -m autolesson practice --clear-record
```

`--clear-record` 只清空完成记录，保留答题缓存。注意：暂存但未提交的练习会按“已处理”跳过，如果平台端还需要修改/提交，请先手动清理对应记录或整个 state 文件。

## 长题/长图处理的已知限制

较长题目、代码题、图片长题仍然**不够稳定**：

- 页面滚动、截图拼接和 OCR 可能漏掉中间代码/选项；
- 多图或拼接图提交后，模型仍可能返回空内容或选错；
- 极端情况下会跳过该题，不会保证 100% 完整作答；
- 视频弹题默认随机兜底，练习模式失败只跳过、不选择。

因此不要把本项目用于关键考试或需要准确率的场景；练习暂存后必须人工逐题复核。

## LLM 空内容重试与随机兜底（风险功能）

默认行为：

- 大模型返回空内容/无法解析时，先自动重试 `llm.empty_retries` 次（默认 2，即最多 3 次尝试）；
- 如果仍然为空，自动切换输入模式再试一次：图片输入→纯文本，文本输入→题目截图；
- 切换后仍失败则按原逻辑停止（或按配置启用随机兜底），不会乱选。

### 无 LLM 模式

配置：

```yaml
llm:
  enabled: false
```

或者把 `api_key` 留空且环境变量也没有 Key，即进入无 LLM 模式：

- `run` 视频模式仍可用；弹题不调用大模型，直接从可见选项随机选择并通知；
- `auto` 列表模式和 `practice` 测试模式被禁用（CLI 返回错误，GUI 下拉框只保留 run）；
- 不会因为缺少 API 而在弹题处中断观看。

视频弹题默认开启随机兜底：

```yaml
llm:
  fallback_random_enabled: true
```

练习模式不同：**不使用随机兜底**，LLM 多级重试仍失败时只跳过该题、不选择，并通知人工复核。

视频弹题的随机兜底默认开启；需要关闭时显式设为 false：

```yaml
llm:
  empty_retries: 2
  empty_retry_wait: 1.0
  fallback_random_enabled: false
```

开启时脚本会：

1. 在题目选项中随机选择一个；
2. 保存弹窗/练习题截图到 `runtime/shots/llm-fallback-*.png`；
3. 发送“自动答题风险兜底（随机选择）”警告通知；
4. 继续作答/暂存，不中断整个任务。

> **⚠️ 风险警告**
> - 随机答案**很可能答错**，视频弹题会被平台判错；
> - 练习虽然仍然只暂存、不提交，但随机答案会被暂存，必须人工检查后再决定是否提交；
> - 该功能默认关闭，只建议在你明确接受风险、并且会人工复核时开启；
> - 视频弹题随机答错后会强制关闭弹窗并继续播放，不会因为判错中断整个挂机，但该题成绩会错误。

## 八、Token 节约策略

1. **只有弹题才调用大模型**；目录、进度、弹窗全部走 OCR/颜色识别。
2. 普通文字题只发题干 + 选项文本；只有以下情况才附带截图：
   - 解析出的选项少于 2 个；
   - 题干含“行列式/矩阵/计算/积分/极限”等数学词且文字较短；
   - OCR 平均置信度低于 0.55。
3. 截图只裁剪弹窗内部，缩放到最大宽度 1100px、JPEG 质量 82；DeepSeek 单张图片最多约 1024 tokens。
4. `max_tokens=400`，`temperature=0`，默认关闭 thinking，要求只输出短 JSON。
5. 开启 DeepSeek JSON Output，减少“解析失败再重试”的额外调用。
6. **答案缓存**：同一道题（题干+选项哈希）只问一次；平台公布“正确答案”后也会写入缓存。
7. 日志只记录题目摘要与答案，不记录 API Key；不会把整屏截图发给模型。

## 十一、常见问题

**Q：自动定位的面板位置偏了怎么办？**
运行 `python -m autolesson calibrate`，查看标注图，把打印出的 `panel_left` / `panel_top` 写进 `config.yaml` 的 `layout` 段。

**Q：识别不到视频 / 状态全是未学习？**
- 确认页面还在课程学习页，且右侧目录已加载；
- 目录文字太小时，把 `panel.ocr_upscale` 调到 `1.3`；
- 状态图标识别不到时，把 `panel.right_icon_width` 从 62 调到 70。

**Q：弹题出现但脚本没反应？**
把 `overlay.card_threshold` 从 225 调低到 210~220；或运行 `python -m autolesson inspect --image <截图>` 查看是否被识别为 `quiz`。

**Q：白色 PPT 被误判为弹窗？**
脚本已经用尺寸/位置/文字二次确认；如仍误判，把 `overlay.card_threshold` 调高到 235~240。

**Q：视频不自动播放？**
脚本会先点播放按钮，再点击视频画面。若浏览器处于后台，请保持窗口前台；脚本会尝试用 pygetwindow 激活。

**Q：可以锁屏/最小化吗？**
不可以。纯视觉方案必须能截到画面。锁屏会导致屏幕全黑并立即停止通知。

**Q：多显示器？**
在 `config.yaml` 设置 `runtime.monitor: 2`，或在命令行加 `--monitor 2`。脚本会自动补偿副屏的坐标偏移；请确保浏览器窗口完整位于该显示器内。

**Q：右侧目录看不到 / 面板定位失败？**
- 退出播放器全屏（全屏后目录会被隐藏）；
- 切回白昼模式（深色模式下浅色弹窗/进度条识别会失效）；
- 运行 `python -m autolesson calibrate` 查看标注图，必要时手动填 `layout.panel_left/panel_top`。

**Q：章节被折叠了怎么办？**
脚本不会点击章节标题（避免误触），请在开始前手动展开所有章节。

**Q：一次能跑多个科目吗？**
一个进程处理当前打开科目的全部视频。换科目后重新运行即可，已完成记录会保留在 `runtime/state.json`。

**Q：弹题一次有多页怎么办？**
当前版本处理弹窗中可见的题目并关闭。若平台要求逐页作答，脚本会在关闭失败时停止并通知，避免乱点。

**Q：DeepSeek V4.1 Flash 还需要单独配置 vision_model 吗？**
不需要。`deepseek-flash` 原生支持图片，`vision_model` 留空就会复用 `model`；只有使用“文字模型 + 另一个视觉模型”的组合时才需要单独填写。

**Q：为什么默认关闭 thinking？**
弹题是选择题，关闭思考模式可以显著降低延迟和输出 token；需要更充分的推理时把 `llm.thinking` 改成 `true` 即可（此时 `temperature` 不生效）。

**Q：JSON 模式返回空内容怎么办？**
脚本会自动去掉 `response_format` 再试一次；仍为空则按故障停止并通知，不会随机猜答案。

**Q：运行时 CPU 占用很高怎么办？**
默认已经把 OCR 限制到 1 个 ONNX Runtime 线程、OpenCV 1 个线程，并且滚动时不再逐格 OCR。如果 OCR 太慢、CPU 还有余量，把 `ocr.intra_threads` 调到 `2~4`。

**Q：开始扫描视频时鼠标滚动很慢怎么办？**
旧逻辑每滚一格都会做 2~3 次 OCR 和固定等待，现在改成“滚轮 + 图像指纹 + 每页一次 OCR”，并会在目录稳定后提前结束等待。仍嫌慢可把 `panel.scroll_step` 调到 `-8 ~ -10`。

**Q：视频明明在播，日志却说“视频播放器未加载出进度条”？**
已修复两个原因：

1. 旧逻辑要求进度条 80% 像素是浅色，视频播到 70% 后蓝色已播部分占大多数会失败；现在按“浅色未播轨道 + 蓝色已播部分”识别。
2. Windows 任务栏的亮色搜索框/蓝色图标在屏幕最底部，旧逻辑“取最靠下的一组”会把任务栏当成进度条，真正的播放器进度条反而被忽略。现在默认排除屏幕底部 5% 的任务栏区域（`player.bottom_margin_ratio`）。

77% 进度截图和“任务栏在底部、视频正在播放”的完整屏幕截图都已加入回归测试。

**Q：失败后为什么跳到了别的视频，然后立即报“重复失败”？**
已修复：现在失败后会先 `_find_lesson_anywhere` 定位回同一个视频并重试一次；`runtime.max_lesson_attempts` 控制连续失败次数，默认 2 次后才停止。

**Q：目录扫描一直翻到 40 页还不结束？**
已修复：滚动指纹只比较目录文字区域，排除了右侧状态图标、滚动条和加载动画；这些东西变化不会再被误判成“目录滚动了一页”。

**Q：会不会被平台检测到？**
脚本模拟人类鼠标移动并加入随机抖动，但**不保证**不被检测。请自行评估风险。

## 十二、已知限制

- 纯视觉方案依赖固定 UI。平台改版后需要更新识别规则。
- 目录标题过长、被省略号截断时，脚本用前几个字/索引匹配；极端情况下可能匹配错误。
- 弹窗内多页题目只处理当前页（见上）。
- 折叠章节不会自动展开。
- 2K/4K、深色模式、浏览器缩放都会影响识别；已做 DPI 适配和自动标定，但首次使用建议先 `--max-lessons 1` 观察。
- OCR 对艺术字/公式识别有限；数学题依赖模型的视觉能力，纯文本模型会自动降级为文字作答。
- 平台的风控、人脸识别、验证码出现时脚本会停止，不会尝试绕过。
